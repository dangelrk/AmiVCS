AmiVCS

Handbuch – Versionsverwaltung für den Amiga und den PC · Stand 27.09.2026 (Programmversion 0.1)

AmiVCS ist eine kleine, bewusst einfach gehaltene Versionsverwaltung für AmigaOS 3.x und den PC (macOS/Linux/Windows). Fast alles läuft rein lokal im Arbeitsverzeichnis; ein Server wird nur für clone, push und pull gebraucht. AmiVCS ist kein Git-Nachbau: Es übernimmt bewährte Grundideen (Commit, Tree und Blob, Branches, dateiweises Vormerken, 3-Wege-Merge), verzichtet aber bewusst auf Rebase, Cherry-Pick, Stash, Reflog und Ähnliches. Ziel ist ein System, das auf einem 68000 ohne FPU flüssig läuft und das man komplett verstehen kann.

  PC-Client (libcurl)  ─┐   HTTPS   ┌──────────────────────────────────┐
                        ├──────────►│ Webserver + PHP (server/)        │
  Amiga-Client (AmiSSL)─┘           │  api.php  Objekt-/Ref-Speicher   │
          │                         │  web.php  nur lesende Ansicht    │
          │ lokal, ohne Server      │  MariaDB  Benutzer, Repos, Refs  │
          ▼                         │  Storage  Objekte als Dateien    │
  Arbeitsverzeichnis + .amivcs/     └──────────────────────────────────┘
  init · add · commit · log · branch · switch · merge · gc
BestandteilPlattformZweck
amivcsAmiga + PCKommandozeilen-Client, alle Befehle
amivcs-guiAmiga (MUI) / PC (Qt 6)Oberfläche im Stil von „git gui“
AMIVCSPrefsAmigaEinstellungs-Editor für amivcs.cfg
Server (server/)Webserverspeichert nur Objekte und Branch-Zeiger; dazu eine nur lesende Web-Oberfläche

Jedes Repository ist ein ganz normales Verzeichnis. AmiVCS legt darin das Unterverzeichnis .amivcs und die Datei .amivcsignore an; alles andere gehört Ihnen. AmiVCS ist von AmiCloud vollständig getrennt: eigener Server, eigene Datenbank, eigene Konfigurationsdatei, eigene Zugangsdaten.

1. Voraussetzungen

WasWofür
AmigaOS 3.x, 68000 oder besseralle Amiga-Programme (keine FPU nötig)
TCP/IP-Stack mit bsdsocket.library (z. B. Roadshow, AmiTCP, Miami)clone/push/pull in amivcs und amivcs-gui
AmiSSL 5 (amisslmaster.library)wie oben – alle Verbindungen laufen über HTTPS
MUI 3.8 oder neuer (muimaster.library ≥ 19)nur amivcs-gui auf dem Amiga
Intuition/GadTools (im Betriebssystem)AMIVCSPrefs
PC: libcurl; für die Oberfläche Qt 6amivcs bzw. amivcs-gui auf macOS/Linux/Windows
Lokal ohne Netzwerk – wie git
amivcs und amivcs-gui öffnen Netzwerk und AmiSSL erst bei clone, push oder pull; alles andere funktioniert ohne TCP/IP-Stack. Fehlt dann etwas, meldet amivcs-gui die Ursache in einem Requester (z. B. cannot open bsdsocket.library) und bleibt geöffnet.

Stack: Alle Amiga-Programme fordern selbst 64 KB Stack an; der Startcode von vbcc legt bei Bedarf einen größeren Stack an. Ein vorheriges Stack ist nicht nötig.

2. Installation auf dem Amiga

Das Archiv AmiVCS.lha enthält die Schublade AmiVCS:

AmiVCS/
  Install-AmiVCS     Installationsskript
  Uninstall-AmiVCS   Deinstallationsskript
  ReadMe             Kurzbeschreibung
  LICENSE            Lizenztext (GPLv3)
  THIRD-PARTY-NOTICES  Lizenz der Fremdkomponente Parson (MIT)
  C/                 amivcs, amivcs-gui, AMIVCSPrefs
  Docs/              AmiVCS.guide
  Examples/          amivcs.cfg.example
lha x AmiVCS.lha RAM:
CD RAM:AmiVCS
Execute Install-AmiVCS

Das Skript fragt jeden Schritt einzeln ab (Antwort y oder n): amivcs und amivcs-gui nach C:, AMIVCSPrefs nach SYS:Prefs/, das AmigaGuide-Handbuch nach HELP: (nur wenn der Assign existiert). Es warnt, wenn muimaster.library oder amisslmaster.library in LIBS: fehlen, und bietet am Ende an, AMIVCSPrefs zu starten, falls es noch keine ENVARC:amivcs.cfg gibt. Vorhandene Konfigurationen werden nie überschrieben. Es wird kein DOS-Treiber installiert und nichts gemountet – AmiVCS enthält keinen Handler.

Manuelle Installation

Datei aus der SchubladeZiel
C/amivcsC:
C/amivcs-guiC: (oder eine beliebige Schublade)
C/AMIVCSPrefsSYS:Prefs/
Docs/AmiVCS.guideHELP: (oder beliebig)

Es werden keine Icons mitgeliefert. AMIVCSPrefs startet man im Shell mit SYS:Prefs/AMIVCSPrefs; auf der Workbench ist es nur sichtbar, wenn im Fenster „Alle Dateien anzeigen“ eingeschaltet ist. Für amivcs-gui kann ein Projekt-Icon angelegt werden; es versteht die Merkmale (Tooltypes) REPO=<pfad> und DEBUG.

Deinstallation

Execute Uninstall-AmiVCS aus der Schublade löscht C:amivcs, C:amivcs-gui, SYS:Prefs/AMIVCSPrefs und HELP:AmiVCS.guide und fragt, ob auch ENV:amivcs.cfg und ENVARC:amivcs.cfg entfernt werden sollen. Ihre Repositories bleiben unberührt.

3. Installation auf dem PC

Auf macOS, Linux und Windows werden die Programme aus den Quellen gebaut (Kapitel 19) und installiert:

make pc                 # bin/pc/amivcs
make qt                 # bin/pc/amivcs-gui
sudo make install       # nach /usr/local/bin (PREFIX=..., DESTDIR=... möglich)

4. Konfigurationsdatei

Nur für clone, push und pull nötig – mit einer Ausnahme: user ist auch der Autorname Ihrer Commits. Eigene Datei, nicht amicloud.cfg.

ProgrammSuchreihenfolge
amivcs (Amiga)-c <datei>, sonst ENV:amivcs.cfg, sonst amivcs.cfg im aktuellen Verzeichnis
amivcs (macOS/Linux)-c <datei>, sonst ~/.amivcsrc
amivcs (Windows-Build)-c <datei>, sonst amivcs.cfg im aktuellen Verzeichnis
amivcs-gui (MUI)ENV:amivcs.cfg, sonst amivcs.cfg im aktuellen Verzeichnis
amivcs-gui (Qt)~/.amivcsrc
AMIVCSPrefsENV:amivcs.cfg, sonst ENVARC:amivcs.cfg

Auf dem Amiga gehört die Datei dauerhaft nach ENVARC:; beim Systemstart kopiert AmigaOS sie nach ENV:. Format: eine Einstellung pro Zeile als schlüssel=wert, Zeilen mit # am Anfang sind Kommentare.

server=https://amivcs.example.com
user=bob
pass=geheim
#verify_ssl=1
SchlüsselBedeutung
serverBasis-URL des AmiVCS-Servers, ohne /api.php; ein abschließender / wird entfernt. Auf dem Amiga nur https://
user (auch username)Benutzername am Server und Commit-Autor (amivcs log); ohne user heißt der Autor „unknown“
pass (auch password)Passwort am Server (im Klartext in der Datei)
verify_ssl1 = Zertifikat prüfen (Standard), 0 = nicht prüfen, nur zum Testen

Der gemeinsame Parser kennt außerdem basepath, debug, gmt_offset und dst; AmiVCS wertet diese nicht aus. Den Autor für einen einzelnen Aufruf ändert amivcs --author "Ronny" commit -a -m "Text".

5. AMIVCSPrefs Amiga

Einstellungs-Editor für amivcs.cfg im Stil der Workbench-Voreinsteller, Aufruf SYS:Prefs/AMIVCSPrefs. Felder: Server, Benutzer (= Autor), Passwort, Zertifikat prüfen.

KnopfWirkung
Speichernschreibt ENVARC:amivcs.cfg und ENV:amivcs.cfg – gilt sofort und dauerhaft
Benutzenschreibt nur ENV:amivcs.cfg – gilt bis zum Neustart
Abbrechenschreibt nichts

Beim Öffnen wird ENV:amivcs.cfg gelesen, ersatzweise ENVARC:. Weichen beide ab, meldet die Statuszeile „ENV:/ENVARC: unterscheiden sich (angezeigt: ENV:)“.

6. amivcs – Aufruf und Optionen Amiga + PC

amivcs [--author <name>] [-c <datei>] <befehl> [argumente]
Option (vor dem Befehl)Bedeutung
--author <name>Commit-Autor für diesen Aufruf
-c <datei>andere Konfigurationsdatei verwenden
Immer im Wurzelverzeichnis aufrufen
amivcs muss im Wurzelverzeichnis des Repositorys (dort, wo .amivcs liegt) aufgerufen werden. Anders als Git wird nicht in übergeordneten Verzeichnissen gesucht. Ausnahmen: init und clone. Pfade bei add/remove sind relativ zum Repository, z. B. src/main.c.

Ohne oder mit unbekanntem Befehl zeigt amivcs eine kurze Hilfe. Rückgabewert 0 bei Erfolg, sonst ungleich 0.

8. amivcs – Server-Befehle

Brauchen server, user und pass in der Konfigurationsdatei (auf dem Amiga außerdem TCP/IP-Stack und AmiSSL). Der Fortschritt wird laufend angezeigt.

BefehlWirkung
clone <repo> [verz]holt das Server-Repository in ein neues Verzeichnis (Standard: Name des Repositorys), legt alle Branches an, checkt main aus (sonst den ersten Branch) und merkt sich den Namen in .amivcs/config
push [<repo>]lädt den aktuellen Branch hoch (nur fehlende Objekte, dann den Branch-Zeiger). Mit <repo> wird dieses Server-Repository benutzt, gemerkt und bei Bedarf angelegt; ohne gilt das gemerkte
pull [<branch>]holt den Branch (Standard: gleichnamig zum aktuellen) und führt ihn wie merge zusammen

Repository-Namen: Buchstaben, Ziffern, _, ., -, höchstens 128 Zeichen. Jeder Benutzer sieht nur seine eigenen Repositories.

push überschreibt nie fremde Commits
Hat jemand vor Ihnen gepusht, lehnt push ab: rejected -- the server has commits you don't have; pull and merge first. Dann amivcs pull, ggf. Konflikte lösen, erneut amivcs push. Der Server selbst prüft nur per Compare-and-Swap, ob sich der Branch zwischenzeitlich geändert hat.
# Amiga
amivcs init
amivcs commit -a -m "Start"
amivcs push projekt-x          # legt projekt-x auf dem Server an

# PC
amivcs clone projekt-x
cd projekt-x
amivcs commit -a -m "Vom PC"
amivcs push

# Amiga
amivcs pull

9. amivcs-gui (MUI) Amiga

amivcs-gui [-v] [<pfad>]

<pfad> ist das zu öffnende Repository (Standard: aktuelles Verzeichnis), -v gibt Fehlermeldungen im Shell-Fenster aus. Von der Workbench aus übernehmen die Merkmale REPO=<pfad> und DEBUG diese Aufgaben. Ist das Verzeichnis noch kein Repository, bietet amivcs-gui an, eines anzulegen (auch: Menü Repository > Init Repository Here).

  • Oben Repository-Pfad und aktueller Branch.
  • Listen Not staged und To be committed mit den Knöpfen Stage ->, Stage All, <- Unstage; Mehrfachauswahl mit der Umschalttaste.
  • Commit-Zeile mit Umschalter -a: OFF/ON und Knopf Commit.
  • History: Historie aller Branches mit den Spalten Graph, OID, Author, Date, Message; der Graph besteht aus Zeichen (| * , |/ ), Branch-Namen stehen in eckigen Klammern vor der Nachricht.
  • Knopfleiste: Refresh, New Branch, Switch, Merge, Clone, Push, Pull, Quit.
  • Menüs: Project (About…, Quit), Repository (Init Repository Here, Refresh, New Branch…, Switch Branch…, Merge Branch…), Remote (Clone…, Push, Pull).

Switch und Merge zeigen zuerst die vorhandenen Branches an, danach wird der Name eingetippt. Fehlen für Clone/Push/Pull Server, Benutzer oder Passwort in amivcs.cfg, fragt das Programm danach; diese Eingaben gelten nur bis zum Programmende. Während der Übertragung erscheint ein Fenster „Working...“ mit Abbrechen-Knopf.

Erstes Push über die Kommandozeile
Push und Pull der Oberfläche benutzen immer das gemerkte Server-Repository. Ein frisch mit init angelegtes Repository muss daher einmal mit amivcs push <name> verknüpft werden. Geklonte Repositories sind bereits verknüpft. (Gilt ebenso für die Qt-Fassung.)

10. amivcs-gui (Qt) PC

amivcs-gui [<pfad>]      # außerdem --help, --version

Dieselbe Oberfläche für macOS, Linux und Windows; Konfiguration ~/.amivcsrc. Unterschiede zur MUI-Fassung:

  • Vormerken und Zurücknehmen auch per Doppelklick.
  • Häkchen „Stage all changes before commit (-a)“.
  • Switch/Merge bieten die Branches in einer Auswahlliste an.
  • Clone fragt den Namen auf dem Server und wählt das Zielverzeichnis per Dateidialog.
  • Der Commit-Graph wird grafisch gezeichnet.
  • Menüs Repository, Remote, Help; Refresh zusätzlich in der Werkzeugleiste.
  • Fehlende Zugangsdaten fragt der Dialog „AMIVCS - Remote Server“ ab (Server URL, Username, Password, Verify TLS certificate) – nur bis zum Programmende.

12. Konflikte auflösen

merge und pull arbeiten dateiweise. Haben beide Seiten dieselbe Datei unterschiedlich geändert (oder eine Seite geändert, die andere gelöscht), ist das ein Konflikt. AmiVCS löst Konflikte nie automatisch:

  • Für jeden Konflikt erscheint conflict: <pfad>.
  • Die Datei behält Ihren eigenen Inhalt; die Fassung der anderen Seite liegt daneben als <pfad>.theirs.
  • Konfliktfreie Änderungen der anderen Seite stehen bereits im Arbeitsverzeichnis.
  • Es entsteht kein Commit („the merge was NOT completed“).
Nur ein konfliktfreier Merge verbindet die Historien
Nur ein konfliktfreies merge/pull erzeugt einen Merge-Commit mit zwei Eltern. Ein von Hand „gelöster“ Commit hat nur einen Elternteil – ein erneutes merge/pull meldet denselben Konflikt dann wieder, und push wird weiter abgelehnt.

Bewährter Weg (Amiga-Befehle; auf dem PC entsprechend cp/rm):

; 1. eigene Fassung sichern, die der Gegenseite übernehmen
Copy datei datei.mine
Copy datei.theirs datei
Delete datei.theirs
; 2. committen und erneut zusammenführen -> "Merge completed."
amivcs commit -a -m "Stand der Gegenseite übernommen"
amivcs merge <branch>          ; bzw. amivcs pull
; 3. eigene Änderungen aus datei.mine einarbeiten, datei.mine löschen
amivcs commit -a -m "Konflikt aufgelöst"
; 4. ggf. amivcs push

Merge-Commits tragen den Autor amivcs und die Nachricht Merge branch '<name>'. merge, pull, switch und checkout verweigern die Arbeit, solange es ungesicherte Änderungen gibt.

13. .amivcsignore

Die Datei im Wurzelverzeichnis listet, was nicht versioniert werden soll. amivcs init legt sie so an:

# AMIVCS default ignore patterns
.amivcs/
#?.o
#?.lib
bin/
obj/
  • Eine Zeile = ein Muster; # am Zeilenanfang ist ein Kommentar – außer bei #?, dem AmigaDOS-Joker.
  • Joker: */? und #?/? auf allen Plattformen; auf dem Amiga zusätzlich die volle AmigaDOS-Mustersprache.
  • / am Ende: nur Verzeichnisse.
  • Ohne / im Muster: gilt für den Dateinamen in jeder Ebene (bin/ trifft jedes Verzeichnis namens bin).
  • Mit / im Muster (/build, docs/*.log, **/tmp/): an der Wurzel verankert, Ebene für Ebene; * springt nie über /, ein Segment ** steht für beliebig viele (auch null) Ebenen.
  • .amivcs wird immer ignoriert.

status, commit, checkout und ein rekursives add <verzeichnis> beachten die Muster; ein ausdrücklich genannter Pfad wird trotzdem vorgemerkt. Beim Branch-Wechsel bleiben ignorierte Dateien stehen.

14. Objektmodell und Grenzen

Objekte sind kompakt binär kodiert, ohne Gleitkommazahlen (Zeitstempel sind ganze Sekunden in UTC) und ohne Kompression.

ObjektInhalt
Blobrohe Dateibytes; OID = MD5 des Inhalts (32 Hex-Zeichen), gleicher Inhalt wird nur einmal gespeichert
Treeeine Verzeichnisebene: sortierte Liste aus Name, Typ, OID
CommitTree-OID, 0–2 Eltern, Zeitstempel, Autor, Nachricht
BranchName + Commit-OID; alle Branches in einer Datei packed-refs (spart Verzeichniseinträge auf FFS)
.amivcs/
  HEAD               aktueller Branch
  packed-refs        alle Branches
  index              Vormerkungen (die OID eines Trees)
  config             gemerktes Server-Repository (remote_repo=...)
  objects/<2>/<30>   lose Objekte
  objects/pack/      Pack-Dateien aus "amivcs gc"

Bewusste Grenzen der Version 1:

  • Vormerken nur für ganze Dateien; Merge nur dateiweise, keine zeilenweise Zusammenführung; kein Diff-Befehl.
  • amivcs log zeigt nur die erste Elternlinie.
  • Kein Aufstieg in übergeordnete Verzeichnisse.
  • Kein Rebase, Cherry-Pick, Stash, Reflog, keine Tags, keine signierten Commits.
  • Auf dem Server nur eigene Repositories, keine Team-Repositories.
  • Größte Datei = AMIVCS_MAX_UPLOAD des Servers (Standard 100 MB).

15. Server einrichten

Der Server (server/) läuft auf einem gewöhnlichen Webserver: PHP ≥ 7.4 mit pdo_mysql, MariaDB oder MySQL, HTTPS-Zertifikat. Er gehört in die Wurzel eines eigenen vHosts (web.php leitet auf /web.php um). Die ausführliche Schritt-für-Schritt-Anleitung steht in docs/INSTALL.md im Quellarchiv; Kurzfassung für AlmaLinux/RHEL mit Apache:

# vHost amivcs.example.com mit DocumentRoot /var/www/amivcs,
# AllowOverride All; dann HTTPS:
sudo certbot --apache -d amivcs.example.com

sudo mkdir -p /var/www/amivcs /var/amivcs-storage
sudo cp -r server/. /var/www/amivcs/          # inkl. .htaccess
sudo cp /var/www/amivcs/config.php.example /var/www/amivcs/config.php
sudo nano /var/www/amivcs/config.php
sudo chown -R apache:apache /var/www/amivcs /var/amivcs-storage
sudo chmod 750 /var/amivcs-storage

sudo mysql < /var/www/amivcs/sql/schema.sql
sudo mysql -e "CREATE USER 'amivcs'@'localhost' IDENTIFIED BY 'geheim';
  GRANT SELECT, INSERT, UPDATE, DELETE ON amivcs.* TO 'amivcs'@'localhost';"

php -r "echo password_hash('geheim', PASSWORD_BCRYPT), PHP_EOL;"
sudo mysql amivcs -e \
  "INSERT INTO users (username, pass_hash) VALUES ('bob', '\$2y\$10\$...');"

sudo systemctl reload httpd
curl -u bob:geheim "https://amivcs.example.com/api.php?action=status"
# -> {"status":"ok","version":"0.1"}
Konstante in config.phpBedeutung
AMIVCS_DB_HOST, AMIVCS_DB_NAME, AMIVCS_DB_USER, AMIVCS_DB_PASSDatenbankzugang (eigene Datenbank amivcs)
AMIVCS_STORAGE_PATHObjektspeicher, außerhalb des Web-Roots; Objekte unter <pfad>/<benutzer>/<repo>/objects/<2>/<30>
AMIVCS_MAX_UPLOADgrößtes Objekt in Bytes (Standard 100 MB); post_max_size in php.ini passend setzen
AMIVCS_ALLOW_HTTPnur für lokale Tests (php -S): erlaubt Klartext-HTTP – nie in Produktion

Auf den Clients genügt dann server=https://amivcs.example.com. Repositories entstehen beim ersten amivcs push <name>. Datensicherung: Datenbank und Speicherverzeichnis gemeinsam sichern.

16. Web-Oberfläche Browser

Unter https://amivcs.example.com/web.php sehen Sie Ihre Repositories im Browser – Anmeldung mit denselben Zugangsdaten wie in amivcs.cfg. Angezeigt werden die Liste Ihrer Repositories (Anzahl der Branches, Datum) und je Repository alle Branches sowie die vollständige Historie aller Branches mit einem kleinen Graphen.

Die Web-Oberfläche ist nur zum Ansehen da: kein Datei-Browser, kein Diff, kein Anlegen von Repositories, kein Commit/Push/Pull. Sie läuft nur über HTTPS, mit eigener Sitzung (Cookie SameSite=Strict) und CSRF-Schutz beim Anmelden.

17. Server-API

https://<host>/api.php?action=…, HTTP-Basic-Auth bei jeder Anfrage. Antworten: {"status":"ok",…} bzw. {"status":"error","code":N,"message":"…"}; get-object liefert die Rohdaten.

AktionBedeutung
statusVersion/Erreichbarkeit
create-repo&repo=Repository für den angemeldeten Benutzer anlegen (409, falls vorhanden)
refs&repo=alle Branches (Name + OID)
has&repo=&oids=welche der kommagetrennten OIDs schon vorhanden sind
put-object&repo=&oid=&type=Objekt hochladen (POST, Body = Rohbytes); 422, wenn der Inhalt nicht zur OID passt, 413 bei Übergröße
get-object&repo=&oid=Objekt herunterladen (Header X-Amivcs-Type)
update-ref&repo=&name=&old=&new=Branch per Compare-and-Swap setzen; 409, wenn old nicht mehr stimmt

git clone --recurse-submodules https://github.com/dangelrk/AmiVCS.git
cd AmiVCS
make pc                       # amivcs für den PC
make qt                       # amivcs-gui (Qt 6)
export VBCC=/pfad/zu/vbcc
make amiga                    # Amiga-Programme per vbcc
